# Design

## Context

See proposal.md for motivation. Relevant current state:

- Dependencies are pinned in `requirements.txt` and installed with pip on `python:3.12-slim`.
- `app/db.py` builds the SQLAlchemy engine **at import time** from `get_settings().database_url`, and `app/main.py`
  reads settings at import time too. Whatever starts the app (tests included) must set `DATABASE_URL` before
  importing `app`.
- The schema is created by `Base.metadata.create_all` in the API lifespan and in `app/cli.py`; default categories are
  seeded in the lifespan.
- `EnableBankingClient()` is instantiated directly inside `app/main.py` and `app/sync.py` (no injection point yet).
- Login throttling uses a module-level `LoginThrottle` with `time.monotonic()`; sessions, consent expiry and the sync
  window use `datetime.now()` / `date.today()`.
- The existing `cheles_db-data` volume has the eight application tables with columns matching the models, and no
  rows at the time of writing.
- mypy strict reports 56 errors in 6 files, mostly missing return annotations, bare `dict` and one unnarrowed
  `User | None` in the login route.

## Goals / Non-Goals

**Goals:**
- A reproducible toolchain (uv lockfile) shared by local runs, Docker and CI.
- One characterization test per scenario in `openspec/specs/`, plus tests for the new `platform/service-runtime`
  spec, all green against the current code.
- Schema owned by Alembic, with a safe path for the existing volume.

**Non-Goals:**
- Introducing ports or moving code into bounded contexts. Tests drive behavior through HTTP, the CLI and the
  scheduled job function; they use the ORM models only to arrange state the API cannot create (expired sessions,
  detached accounts) and to assert stored state the API does not expose (`raw`, token hashes, external ids).
- Changing behavior, except making `DATABASE_URL` mandatory.

## Decisions

### uv project layout
`pyproject.toml` declares the runtime dependencies with today's exact versions plus `alembic`, and a `dev` dependency
group (pytest, pytest-cov, testcontainers[postgres], time-machine, ruff, mypy). `.python-version` pins 3.12, matching
the Docker base image. The Dockerfile copies the `uv` binary from the official image at a pinned version and runs
`uv sync --frozen --no-dev`, then puts `.venv/bin` on `PATH`.
*Alternative*: keep pip with `requirements.txt` + a dev file — rejected, no lockfile for transitive dependencies.

### Alembic baseline and startup migration
- `alembic.ini` + `migrations/` at the repo root; `env.py` takes the URL from `get_settings().database_url` and
  `target_metadata` from `app.db.Base`.
- Revision `0001_baseline` is autogenerated against an empty database and reviewed by hand so it reproduces exactly
  what `create_all` produces (verified by comparing `pg_dump --schema-only` of both).
- A new CLI command `python -m app.cli migrate` runs on container start (the Dockerfile `CMD` becomes a small shell
  form: migrate, then `exec uvicorn …`). It inspects the database: if application tables exist but `alembic_version`
  does not, it stamps `0001_baseline`; then it runs `upgrade head`.
- The API lifespan no longer calls `create_all`; it still seeds default categories. `create-user` runs the same
  migrate routine before writing, so it keeps working on an empty database.
*Alternative*: run migrations inside the FastAPI lifespan — rejected: it would couple every test client start to
Alembic and make multi-worker startups race.

### Required `DATABASE_URL`
`Settings.database_url` loses its default, so pydantic-settings raises a validation error naming the field when it is
missing. `.env.example` documents it for runs outside Docker. Compose keeps building it from `DB_PASSWORD`.

### Test architecture
- `tests/` mirrors the specs: `tests/identity/test_user_authentication.py`, `tests/banking/test_bank_sync.py`, … and
  `tests/platform/test_service_runtime.py`. Each test is named after its scenario and its docstring quotes the
  scenario title, so specs and tests can be cross-checked.
- **Database**: a session-scoped Postgres 16 container (testcontainers) is started in `conftest.py` before `app` is
  imported, `DATABASE_URL` is exported, and `alembic upgrade head` runs once. Before each test all application tables
  are truncated and default categories re-seeded, and the module-level login throttle is cleared.
- **HTTP**: FastAPI `TestClient` used as a context manager (runs the lifespan, so seeding is exercised), with
  `follow_redirects=False` for the bank callback.
- **Enable Banking**: a `FakeEnableBanking` in `tests/fakes.py` implements the client's public methods with in-memory
  banks, sessions, accounts, paged transactions, balances, call recording and error injection. It is installed by
  monkeypatching the `EnableBankingClient` name in `app.main` and `app.sync`. When the hexagonal skeleton introduces a
  port, the fake becomes its test adapter.
- **Time**: `time-machine` controls wall-clock time (sessions, consent, sync window, TOTP periods); the throttle's
  sliding window is tested by monkeypatching `time.monotonic` as seen from `app.security`.
- **Client IP**: Starlette 0.41's `TestClient` cannot set the client address, so per-IP throttle tests wrap the app in
  a tiny ASGI middleware (test-only) that sets `scope["client"]` from an `X-Test-Client-IP` header.
- **CLI**: `create_user` is called with `getpass` monkeypatched and stdout captured; `migrate` is run against
  dedicated throwaway databases for the runtime-spec scenarios (empty, pre-migration with rows, up to date).
- **Schema equivalence**: one test creates a database with `create_all` and another with migrations and compares
  their `pg_dump --schema-only` output (run inside the Postgres container), ignoring `alembic_version`.

### Static checks
- ruff with line length 120 and rules `E, F, W, I, UP, B, SIM, RUF`; `ruff format` applied once to the whole codebase
  in its own task so the reformatting diff is isolated.
- mypy `strict = true` for `app/`, `migrations/` and `tests/`, with the `pydantic.mypy` plugin and
  `ignore_missing_imports` only for third-party packages without type information (apscheduler, qrcode, pyotp if
  needed). Fixes in `app/` are annotations and narrowing only (e.g. asserting the user exists after the combined
  credential check), never logic changes.
- Coverage is reported in CI; `fail_under` is set to the measured coverage rounded down, as a ratchet.

### CI
`.github/workflows/ci.yml` on `push` to `main` and `pull_request`: checkout, `astral-sh/setup-uv` (pinned), `uv sync
--frozen`, `ruff check`, `ruff format --check`, `mypy`, `pytest --cov`. Ubuntu runners include Docker, which
testcontainers needs. The repos are private; usage stays within the free monthly minutes and the account's spending
limit prevents charges.

### Placement of new pieces
No entities, value objects, ports or adapters are introduced in `app/`. `tests/fakes.py` is test-only. No VO decisions
apply. The Alembic baseline is the first migration.

## Risks / Trade-offs

- [Baseline differs from a real pre-migration database] → The schema-equivalence test compares migrated vs
  `create_all` output; before stamping the real volume, its schema dump is diffed against a freshly migrated one, and
  the apply pauses if they differ.
- [Characterization tests encode the known defects (⇄ mark, observations)] → Intended: the fix changes will flip those
  tests explicitly, alongside a MODIFIED spec.
- [Tests import ORM models for setup and stored-state assertions] → Confined to arrange/assert steps; when the
  skeleton change moves the models, those imports move to persistence fixtures per context.
- [Monkeypatching module-level names couples tests to today's module layout] → Limited to two names
  (`app.main.EnableBankingClient`, `app.sync.EnableBankingClient`) in one fixture, replaced by port injection in the
  skeleton change.
- [Import-time engine creation] → Handled by ordering in `conftest.py`; removed later when the composition root owns
  the engine.
- [Big formatting diff] → Isolated in one commit so review and blame stay readable.
- [Testcontainers needs Docker locally] → Already required to run the app (OrbStack); documented in the README.

## Migration Plan

1. Build the new image; on first start `migrate` stamps the existing volume as `0001_baseline` (no table changes) and
   the API starts as before.
2. Rollback: the previous image still works against the stamped database, because stamping only adds the
   `alembic_version` table, which `create_all` ignores.
